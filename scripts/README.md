# Deployment and end-to-end scripts

Testnet only: NEAR testnet, Base Sepolia, Solana devnet. One style: bash (3.2 or later, the macOS
default works) plus near-cli-rs (`near`), Foundry (`forge`, `cast`), `jq`, `curl` and `shasum`;
`python3` is used only to decode base58; `deploy-engine.sh --reproducible` also needs `git`,
cargo-near 0.22.0 (`cargo near`) and a running Docker, and `pnpm -r test` runs
`lib/deploy-checks.test.ts`, which needs `bash` and `jq`; the end-to-end helpers that need the rose-ibe wasm build, the
Streamflow SDK or `@rose/sdk` run under Node 22.18 or later (the TypeScript ones with Node's native
type stripping, no build step). `scripts` is a workspace package (`@rose/scripts`): `pnpm install`
at the root installs it, and `pnpm --filter @rose/sdk --filter @rose/ibe-wasm build` must have run
once so `@rose/sdk` and `@rose/ibe-wasm` resolve. Keys are read from `$ROSE_CONFIG_DIR`
(default `~/.config/rose`: `evm-deployer.env` with `EVM_DEPLOYER_PRIVATE_KEY`, `solana-ops.json`,
the generated `seed-accounts.json`; [`.env.example`](../.env.example) lists every file) and from
`~/.near-credentials/testnet/<account>.json` (the legacy keychain of near-cli-rs). No script
prints a key or puts one on a command line: cast and forge sign through an encrypted keystore
(`evm-keystore.ts`), near-cli-rs through the keychain. near-cli-rs writes keychain files
world-readable, so `deploy-engine.sh` and `rehearse-keyless.sh` set the files they create to mode
600; do the same once for the parent account (`chmod 700 ~/.near-credentials ~/.near-credentials/testnet`
and `chmod 600 ~/.near-credentials/testnet/<parent>.json`). Every deployment and every end-to-end
run is recorded under `deployments/` (addresses, transaction hashes, block numbers, gas: no
secrets).

| Script | What it does |
|---|---|
| `derive-vault-signer.sh <engine account> [--all]` | Prints the engine's MPC-derived Base vault address (`derived_public_key("vault/base", engine, 0)` mapped to an EVM address exactly as the engine does). The engine account does not need to exist: the derivation only depends on its name. `--all` also prints the Solana vault and gas payer. |
| `deploy-base.sh --engine <engine account> [--role staging\|final] [--signer 0x…] [--demo-assets-from <engine account>]` | Deploys TestUSDC, DemoToken ("Cindral", "CINDR"), DemoStreamFaucet and RoseVault on Base Sepolia with the Foundry scripts in `contracts/evm/script`; `--demo-assets-from` reuses the three demo contracts recorded for another engine and deploys only the RoseVault. Refuses to broadcast unless the RoseVault signer equals `derive-vault-signer.sh` for the engine account (the vault is immutable) and `SABLIER_LOCKUP` of `lib.sh` (the one source of the address, handed to both Foundry scripts through the environment) answers `name()` = "Sablier Lockup NFT"; reads the deployed `SIGNER()` and `LOCKUP()` back afterwards and dies unless they are that signer and that Lockup. |
| `deploy-engine.sh <engine account> [--role staging\|final] [--balance "17 NEAR"] [--rose-vault 0x…] [--wasm <file> \| --reproducible] [--keyless] [--skip-create] [--verify-only]` | Creates the engine as a sub-account of its parent, deploys the engine wasm (`target/near/rose_engine/rose_engine.wasm`, or the artifact `--wasm` names, or with `--reproducible` one it builds first with `cargo near build reproducible-wasm` in a plain clone of HEAD, inside the Docker image pinned in `contracts/engine/Cargo.toml`, kept as `target/near/reproducible/rose_engine-<commit>.wasm`; the clone and the image are removed afterwards; uncommitted changes under `contracts/` are refused) with the `new` init call (MPC `v1.signer-prod.testnet`, domains 0/1/2/3, the live CKD public key, the parent as fee recipient, `tusdc.rose-app.testnet`, the RoseVault and accepted Base cash tokens recorded by `deploy-base.sh`, Sablier Lockup, chain id 84532, Streamflow), calls `bootstrap`. Then, on every path and each read live, never skipped: the on-chain code hash equals the sha256 of the artifact (recorded with its size and build environment before anything is sent), `get_config` equals the init arguments (the CKD public key read again from the MPC), the derived addresses equal the MPC view, the RPC serves Base Sepolia, and the RoseVault in `get_config` answers `SIGNER()` = the engine's `vault/base` address and `LOCKUP()` = the Sablier Lockup. A reproducible artifact's log line names its commit, and HEAD when it is another one. An artifact counts as reproducible when its embedded NEP-330 metadata names the pinned image as `build_environment`, and `--role final` deploys nothing else, nor an artifact whose commit (`source_code_snapshot`) is not on the remote. `--reproducible` cannot resume a stopped run (a rebuild after any new commit differs): resume with `--skip-create --wasm <that run's artifact>`. With `--keyless`, and only once every check passed, it deletes every access key in one transaction (the keychain key that signs it listed last) and polls `view_access_key_list` at `final` for up to 60 s until it returns `[]`. `--role final` refuses to run without `--keyless`. `--skip-create` resumes a stopped run on an existing account (deployment and bootstrap skipped when already done on chain); `--verify-only` sends nothing, rechecks everything and records the result, which recovers a run that stopped after the key deletion. `.near.engine.keyless` is written from the live access key list. |
| `rehearse-keyless.sh <keyless-rehearsal-*.<parent>.testnet> [--wasm file] [--balance "0.02 NEAR"]` | Rehearses the keyless step on a throwaway sub-account with the same `lib.sh` helpers: creates it, deploys a wasm without init (by default a 34-byte module exporting `noop`), adds a second full-access key nobody holds, checks the code hash, deletes both keys in one transaction, polls until `view_access_key_list` returns `[]`, then reruns the checks to show a repeated run sends nothing. Record: `deployments/e2e/<account>.json`. |
| `evm-keystore.ts <name>` | Writes `$ROSE_CONFIG_DIR/keystores/<name>.json`, the encrypted keystore (Web3 Secret Storage v3, scrypt) of the key in `<name>.env`, with a random `<name>.password` (both mode 600), once; prints their paths and the address. `lib.sh`'s `evm_signer` calls it so cast and forge get `--keystore` and `--password-file`, never `--private-key`. |
| `solana-vectors.ts [--check]` | Rebuilds the web3.js legacy message vectors of the engine's Solana encoder (`contracts/engine/tests/vectors/foreign/solana_web3js_messages.json`, mirrored by `packages/sdk/test/chains/fixtures/solana_messages.json`) from web3.js, spl-token and the Streamflow SDK's own instruction builders; `--check` exits non-zero unless both committed files match byte for byte. |
| `e2e-base-tender.sh <engine account> <step\|all\|record> [--holder a] [--issuer b] [--stream id] [--receipt file] [--evm-env name] [--record <step> <near tx hash>]` | Real-testnet flow of a Base position: mint a KOL demo stream, `depositStream` into RoseVault, `register_base_deposit` after the Base safe head (real ForeignTx attestation), fund the Tender in NEAR tUSDC, create the Tender, place a sealed ask (encrypted with the rose-ibe wasm build through `ibe.mjs`), `close` (real CKD key release), `open_bid`, `clear`, `settle_bid`, `claim_base_tokens` (real MPC signature) and `executeTransfer` on RoseVault. State and every hash go to `deployments/e2e/<engine>.json`. `--holder` is required on the first run (then read from the state file); the issuer defaults to `$ROSE_ROOT_ACCOUNT`. The minted stream id comes from the faucet's own `PositionMinted` log and the payout id from the claim's own `payout_requested` event (the Lockup and the engine are shared); a mint or a claim an earlier run sent is resumed, not repeated. `--evm-env` names the `~/.config/rose/<name>.env` holding the EVM holder's key (`EVM_PRIVATE_KEY`; default `evm-deployer`): DemoStreamFaucet lets one address mint one KOL position per day. `--stream <id>` deposits an existing stream of the EVM holder instead of minting one; with `--receipt <file>` (the `cast send --json` receipt of an earlier `depositStream`) the `deposit` step only records that deposit. `record --record <step> <near tx hash>` stores a NEAR transaction sent by hand under a step name, with its gas. |
| `e2e-solana-stream.mjs <engine account> <step\|all> [--holder <near account>] [--case main\|ended]` | Real-devnet flow of a Streamflow position: create a stream of a devnet test SPL token to a holder, `transfer_recipient` to the holder's engine deposit address, `attribute_sol_deposit` (real `AccountState` proof), `move_sol_deposit` (engine-signed move to the vault, broadcast), `register_sol_deposit`, `claim_sol_tokens` drawing on the stream from a durable nonce account and a receipt nonce account created with the claimant's seeds (`createWithSeed(ops, nonceSeedPrefix(holder) + suffix)`, `@rose/sdk`) (engine-built `withdraw` + `TransferChecked` + receipt advance durable-nonce transaction, broadcast), `confirm_sol_payout` (proof that the nonce advanced and the receipt moved with it), then `redeem` of the position (`AdvanceNonceAccount` + `transfer_recipient` to the holder + the receipt's advance, broadcast) and `confirm_sol_redeem`. The stream runs two hours: the engine refuses a stream ending within an hour of its attribution. `--case ended` instead deposits a 65-minute stream and leaves it in the vault until it ends (`wait-end`: Streamflow's auto-claim withdraws its remainder into the vault's token account one second after the end, read at finality), then `sync` (`sync_sol_stream` books it in the class's swept balance), `claim-swept` (`claim_sol_tokens` with no draw and `swept`: `TransferChecked` and the receipt advance only, broadcast) and `confirm` (landed on its receipt); state in `deployments/e2e/<engine>.solana-ended.json`. State in `deployments/e2e/<engine>.solana.json`; `--holder` is required on the first run. `setup` and `claim` record each transaction as soon as it exists and resume instead of minting, creating or claiming twice; the payout id comes from the claim's own event. Honors `ROSE_CONFIG_DIR`, `SOLANA_RPC_URL` and `NEAR_RPC_URL`. |
| `seed.ts [step\|all\|open-round] [--env deployments/<engine>.env] [--window-minutes 12] [--reveal-minutes 5] [--kol-wallet nadia]` (`pnpm --filter @rose/scripts seed`) | Demo seed of spec 9 against the engine named in the env file: the fictional Cindral Foundation and its token Cindral (CINDR); NEAR sub-accounts of the root account (`ROSE_ROOT_ACCOUNT`, default `rose-app.testnet`, whose keychain key must be present) for the issuer and six holders (Halden Ventures, Tessaro Capital, Ines Marlow, Varick Partners, Teodor Vance, Nadia Solvik), funded from it; the Seed Round and KOL Round created in custody with `RoseVault.createStreams` on the DemoStreamFaucet schedules (so positions minted from the app join the same classes), one KOL stream self-deposited with `depositStream`, the Strategic Round as Streamflow streams of a devnet CINDR mint deposited in three engine calls; every log registered through ForeignTx; tUSDC cash on NEAR and on Base; then a Tender (Seed Round, Base tUSDC), an Exit (Strategic Round, NEAR tUSDC, including one deliberately malformed bid) and an Advance (KOL Round) with sealed orders encrypted to the live CKD key. `--kol-wallet` names the key in `seed-accounts.json` that mints and self-deposits Nadia Solvik's own KOL stream (default `nadia`, generated on first use): DemoStreamFaucet allows one mint per address per day, so seeding another engine within 24 h names a fresh key, and the step refuses early with the next mint time otherwise. Steps: `fund`, `base`, `solana`, `register`, `cash`, `rounds`, `summary`; each is recorded once and a run resumes where it stopped. `open-round`, run only when named, leaves an Exit on the Seed Round open for anyone to bid from the app: Halden Ventures' sealed ask, a 14-day window (or `--window-minutes`), the 7-day maximum key timeout and a 24 h reveal window. Records: `deployments/e2e/cindral.json` (engine-independent cast and mint; `cindral.<root>.json` under another root account) and `deployments/e2e/<engine>.seed.json`; keys in `~/.config/rose/seed-accounts.json` and sealed orders in `~/.config/rose/seed-orders/<engine>.json` (both mode 600). `summary` writes the devnet mint to `deployments/testnet.json` and the env file. |
| `e2e-live.ts [step\|all] [--env deployments/<engine>.env]` (`pnpm --filter @rose/scripts e2e:live`) | Drives the seeded rounds to settlement on the real testnets and records every proof in `deployments/e2e/<engine>.live.json`: `cancel-no-key` (an Exit with a 60 s key timeout that nobody closes: `close` refused, `cancel_no_key`, refund), `close` (CKD key release checked against an offline unwrap), `open` (every opening sent by the funder account, which is neither a bidder nor a round creator; the malformed bid cannot be decrypted and its author's own opening must be refused on chain with "Opening does not match the ciphertext"), `clear` (compared with the `@rose/sdk` clearing reference; exits non-zero on a mismatch), `settle` (the malformed bid's bond is slashed), `payouts` (`withdraw_near_cash`, `withdraw_base_cash` + `executeTransfer`, an Advance lien share repaid from unlocks + `executeTransfer` of CINDR, `redeem` + `executeRelease`) and `report` (the markdown table of every transaction). |
| `demo-manifest.ts [--env deployments/<engine>.env]` | Writes the guided demo's data file (`/app/demo`, "Watch a full round") for the engine named in the env file: reads `deployments/e2e/cindral.json`, `deployments/e2e/<engine>.{seed,live}.json` and, when present, `deployments/e2e/<engine>.solana.json` (the Solana payout steps), builds the manifest with the web app's own builder and validator (`apps/web/src/lib/demo/manifest.ts`: every transaction of each settled seeded round grouped by step, the cast's names, the off-chain checks), writes `apps/web/src/content/demo/<engine>.json` and regenerates `apps/web/src/content/demo/index.ts`. The app shows the demo only for the engine it is built with, so after seeding a new engine and running `e2e-live.ts`, this script is all the demo needs. |
| `verify.ts` (`pnpm verify` from the root) | Read-only check of the live deployment against the values the README states, with nothing installed (Node 22.18 or later): 10 checks over NEAR testnet and Base Sepolia (the engine and `tusdc.rose-app.testnet` exist, run their recorded code and have no access key; the engine's code hash, the one the reproducible build produces, and its NEP-330 source; `get_config`, the RoseVault's chain, `SIGNER()` and `LOCKUP()`, the MPC-derived Solana vault and fee payer, and the settled rounds 0, 1, 2 and 7 cleared as the `@rose/sdk` clearing reference recomputes from their openings, loaded from `packages/sdk/src` by a resolve hook). Exits 0 only if every check passes. `NEAR_RPC_URL` and `BASE_SEPOLIA_RPC_URL` replace the endpoint lists (dRPC then FastNEAR; sepolia.base.org then PublicNode) with one URL. |
| `ibe.mjs` | Node wrapper over `packages/ibe-wasm/pkg` (the browser's wasm): `encrypt`, `decrypt`, `plaintext` and `unwrap` (a CKD response to the round key). |
| `lib.sh` | Shared helpers (RPC views, near-cli calls, base58, the deployments file, the keyless helpers `near_require_code`, `near_delete_all_keys` and `near_wait_keyless`, the live pre-deletion checks `require_engine_config`, `require_rose_vault`, `require_base_chain` and `require_sablier_lockup`, `evm_signer`). `lib/deploy-checks.test.ts` runs the checks offline against a stand-in `cast`. Sourced by the bash scripts. |

NEAR views go to `NEAR_RPC_URL` (default `https://test.rpc.fastnear.com`) in the bash scripts and in `e2e-solana-stream.mjs`, which backs off and retries when the RPC answers -429 (rate limited); a step that stopped after its NEAR call can be run again: payout requests (`withdraw_base_cash`, the lien claim, `redeem`) are looked up and resumed, not sent twice.

Order for a new engine account `<engine>` (the final deployment `engine-v2.rose-app.testnet` reused
the demo assets first deployed for the staging engines, as `engine.rose-app.testnet`, which it
superseded, did before it, and a new engine reuses the same ones, so positions
minted from the app stay in the seeded classes; drop `--demo-assets-from` to deploy a new TestUSDC,
DemoToken and DemoStreamFaucet):

```sh
scripts/derive-vault-signer.sh <engine> --all
scripts/rehearse-keyless.sh keyless-rehearsal-$(date +%s).<parent>   # optional dry run of the key deletion, 0.02 NEAR
scripts/deploy-base.sh --engine <engine> --role final --demo-assets-from engine-v2.rose-app.testnet
scripts/deploy-engine.sh <engine> --role final --reproducible --keyless   # Docker running, about 2 GB free
```

If `deploy-engine.sh` stops half way, run it again with `--skip-create` and
`--wasm target/near/reproducible/rose_engine-<commit>.wasm` (the deployment is skipped
when the on-chain code already equals the artifact, the bootstrap when the derived addresses are
stored); if it stops after deleting the keys,
`scripts/deploy-engine.sh <engine> --role final --wasm target/near/reproducible/rose_engine-<commit>.wasm --keyless --verify-only` checks and records the
result without sending anything.

`deployments/testnet.json` then holds everything the web app needs; `deployments/<engine>.env` is
the matching `NEXT_PUBLIC_*` snippet for `apps/web/.env.local` or the Vercel environment.

## Sandbox integration tests

`contracts/engine/tests/sandbox_*.rs` run the engine in a local NEAR sandbox (near-workspaces 0.24,
neard 2.14.0) next to `contracts/mock-mpc` (signs with deterministic test keys; recorded live
responses are replayed only for the payload they were recorded over) and `contracts/tusdc`. They are gated: without `ROSE_SANDBOX=1` each prints a skip line and passes, so
`cargo test --workspace` stays offline and fast. Run them one suite at a time:

```sh
ROSE_SANDBOX=1 cargo test -p rose-engine --test sandbox_lifecycle -- --test-threads=1
ROSE_SANDBOX=1 cargo test -p rose-engine --test sandbox_recorded -- --test-threads=1
ROSE_SANDBOX=1 cargo test -p rose-engine --test sandbox_staging -- --test-threads=1
```

The first run downloads the sandbox binary (73 MB, into `target/debug/build/near-sandbox-*`) and
each suite builds the three contracts with cargo-near. Every test owns its sandbox: the `neard`
child is killed and its home directory removed when the test ends, also on failure, so no process
outlives the run. Each test prints its gas table and asserts every user-facing call stays under
300 Tgas.
